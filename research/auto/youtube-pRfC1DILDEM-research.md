# 【研究ノート】【AI中級】RAGのその先。巨大な資料をAIで精度高く取り扱いたい。 [pRfC1DILDEM]

本ノートは字幕原文 [[youtube-pRfC1DILDEM-transcript]] を元にした二次分析です。

## 独自要約
RAGは類似箇所を検索する仕組みであり、「数」「時間（時系列）」「全体」を問う質問には構造的に答えられない。精度向上には質問を「探し物」「数える」「並べる」「全体」の4分類に仕分け、探し物以外はデータベース定義や要約階層など別の道具へ振る必要がある。また、資料が500ページ未満や更新が速い場合はインデックスを作成せず丸ごと読ませる・その場で探すなど「仕組みを作らない」選択が有効である。RAGのその先とは新技術ではなく、質問の型・資料の量・更新頻度を見極めて道具を使い分けることである。

## 内容の流れ
1. 議事録検索の失敗談と、RAGに構造上答えられない質問があるという問題提起
2. RAGが構造的に答えられない3つの質問（数、時間、全体）
3. 質問の4分類への仕分け（探し物、数える、並べる、全体）
4. 探し物の質問への対処と強化策（コンテキスト付加、キーワード検索、リランキング）
5. 数える質問・並べる（時間）質問への対処（集計定義の作成、2つの時間軸の保持）
6. 全体を問う質問への対処（要約階層の作成または全量読み込み）
7. 仕組みを作らない選択肢（小規模資料での丸ごと渡し、高頻度更新でのその場検索）
8. まとめ：新技術ではなく質問・資料に応じた道具の使い分けとOKFとの補完関係

## 重要な知見
- RAGは意味が近い断片を拾う仕組みであり、探せば見つかるという前提が成り立たない質問には答えられない。「探せ ば 見つかる と いう 前提」
- 検索は「点」を拾う仕組みであるため、数・時系列・全体傾向といった「面」を問う質問には構造的に対応できない。「点 を いくら 集め て も 面 に は」
- 探し物の検索精度を高めるには、切り分けた断片の先頭に何の話題かという文脈を1文追加することが有効である。「何 の 話 の 一部 な の か」
- データベースの数値をAIに集計させる際は、計算式のブレを防ぐため事前に定義を用意しておく必要がある。「この 数字 の こと です と いう 定義」
- 時系列の質問に対応するには、事実が実際に発生した時間とそれを知った時間の2つの軸を保持する必要がある。「この 2 本 を 持た せ て おく」
- 全体を把握する質問に対しては、事前に要約の階層構造を構築するか、検索を介さず全量を読み込ませる。「あかじめ 要約 の 回層 を 作っ て おく」
- 資料が約500ページ未満の場合や更新が速い環境では、インデックスを作成せず直接渡すかその場で探す方が効果的である。「その 場 で 探し に 行く 方 が 良い 結果」
- 課題解決の本質は単一の新技術ではなく、質問の型や資料特性に応じて適切な道具へ割り振ることである。「質問 が 来 た 時 の 振り分け 表」

1. **断片化時の文脈付加による動画研究資料の検索性向上**: 動画の字幕や解説を細かく切り分ける際、冒頭に「どの動画のどの話題か」を示す文脈を1文付加して登録することで、動画研究資料の検索漏れを抑制する。
