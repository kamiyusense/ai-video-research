# AI動画字幕図書館司書猫さん（Windows）

受け箱の動画を選んで「選択保存」、またはURLを貼って「手動保存」する画面です。押したボタンの対象だけを処理します。
ローカルのWebページをEdge／Chromeのアプリ表示で開きます。設計は [v4設計書](../../docs/design/subtitle-switch-v4.md)、画面確認は [静止プレビュー](../../docs/design/preview-v4.html) を参照してください。プレビューはファイルとして開けます。

**実装はオフラインの偽サービスで検証しています。本作業では本番実行をしていません。Windows画面・Claude・YouTube・GitHub保存・Notebook／Drive同期の実機結果はUNKNOWNです。**

## 最初の準備

1. WindowsにPython、EdgeまたはChrome（なければ既定ブラウザ）、Git、yt-dlp、ログイン済みClaude CLI、既存のnotebooklm-py CLIが必要です。画面は標準ライブラリの `http.server` と同梱HTML／CSS／SVGだけで動きます。APIキーは使いません。インストールや課金、ログイン操作はこのアプリでは行いません。
2. GitHub研究室のPC作業フォルダで、保存専用の非defaultブランチ `subtitle-switch/saves` を用意してください。普段の開発用フォルダと分け、未保存の変更が無い作業フォルダを推奨します。アプリはブランチの切替や作成を勝手に行いません。mainにいる場合は停止します。
3. `config.example.json` を `config.local.json` にコピーし、`repository` を上の作業フォルダ、`vault` をPCの保管庫に変更してください。OWNERは自分のWindowsユーザー名に置き換えます。保管庫はGitHub作業フォルダの外に置いてください。
4. Driveデスクトップ同期を使い、`drive_root` をマイドライブの場所にします。受け箱・好み・登録チャンネルは `AI動画研究室/` の中を優先し、旧直下にしか無ければそちらを使います。個別の場所は設定の `inbox`・`preferences`・`channels` で指定できます。
5. `notebook_id` は保存先NotebookのID、`source_limit` は実際のソース上限に合わせます（初期値300、契約上限はUNKNOWN）。NotebookをChromeのCDP接続で開いておいてください。アプリはNotebook接続用Chromeの起動やGoogleの再ログインを行いません。`cdp_port` の初期値は9222です。

本Issueでは実サービスへの実行は禁止です。上記はオーナーが後日、実機実行を許可した際の手順です。

## 起動

このフォルダをエクスプローラーで開き、ターミナルから次を実行します。

```powershell
py -3 subtitle_switch.pyw config.local.json
```

黒い窓を開かずに起動する場合は、Pythonの `pythonw.exe` を使います（実際のインストール先のPATHまたはフルパス）。

```powershell
pythonw subtitle_switch.pyw config.local.json
```

起動コマンドは1回だけです。Edge／Chromeが見つかればアドレス欄・タブのないアプリ窓（初期1280×840）で開きます。どちらも見つからない場合は既定ブラウザで開きます。ブラウザの起動には `CREATE_NO_WINDOW`、既定ブラウザにはWindowsのGUI関連付けを使います。起動したターミナル自体を閉じる仕組みではありません。

画面を閉じると心拍が途切れ、約12秒後にサーバーも終了します。保存・質問・一覧更新の処理中なら、その工程が終わるまで待ってから終了します。ブラウザが開けなかった場合の待ち時間は最大約45秒です。OSの既存インスタンスロックはサーバー終了まで保持します。

旧tkinter画面は起動しません。`switch_app.py` の画面構築を廃止し、保存対象計算等の共通関数を残しました。`subtitle_switch.pyw` に残る旧PowerShell試作関数は移行参照・既存試験用です。

## 画面

上に見出しと全身の司書猫、中央に動画一覧、下に操作欄と保存ボタンがあります。長い一覧はその中だけスクロールし、タイトル列が最も広く伸びます。理由・状態・Notebookの全文はマウスを乗せると表示されます。小さい窓では一覧が縮み、補助操作は内部スクロールできます。

見出しだけ同梱6書体から起動ごとに選び、クリックで次の書体に切り替えます。「猫」は蜜柑と白文字の印です。本文はWindowsの日本語フォントで固定しています。全選択／解除は表の見出しのチェック1個です。チェックは弾く・戻すにも使えますが、弾いた行は保存しません。非表示のチェック行も選択保存から除きます。

全身と顔の猫は待機・処理中・完了・要確認に対応します。右下の猫に近づくと顔を向け、近くでは猫パンチします。`assets/cat_play/` を外しても状態の顔と通常カーソルに戻ります。全身・顔・遊びの寸法やfpsは各manifestに従います。付属の遊び素材は256×192です。

「保存した動画内容をAIに質問」で質問・回答のパネルが開きます。Claudeに送るのは研究ノート最大3本・合計24,000文字と質問最大2,000文字です。既存の `ask_research.py` が送信内容と回答を保管庫内に記録します。Grokは利用できない理由を表示し、無効にしています。

## ローカルサーバーの安全

サーバーは `127.0.0.1` の空きポートだけに公開し、毎回ランダムな合言葉をURL・素材取得・操作に付けます。Hostが実際の `127.0.0.1:<port>` と一致しない要求、合言葉がない要求、他サイトのOriginを拒否します。操作はJSONのPOSTと専用ヘッダーを必須にし、GETで保存等を実行しません。CORSは許可せず、外部フォント・CDNも使いません。アクセスログにURLや合言葉を出しません。

## オフライン試験

リポジトリのルートで `bash .symphony/run_all_tests.sh` を実行します。HTTPはメモリ上の偽接続で実際のハンドラーを通し、AI・動画・ブラウザは偽物を使います。Windowsのブラウザ窓と実サービスの結果は別途実機確認が必要で、今回の試験ではUNKNOWNです。

`python` はMicrosoft Storeのダミーに解決される場合があるため、`py -3` を使います。Pythonランチャーがない場合は、実際のPythonをフルパスで指定します（例：`& "C:\Users\OWNER\AppData\Local\Programs\Python\Python313\python.exe" subtitle_switch.pyw config.local.json`）。`PYTHONUTF8` の設定は不要です。

`claude`・`yt-dlp`・`notebooklm` は `shutil.which()` で `.cmd` / `.exe` を含めて検索します。見つからない場合は `CLAUDE_COMMAND_NOT_FOUND` / `YT_DLP_COMMAND_NOT_FOUND` / `NOTEBOOKLM_COMMAND_NOT_FOUND` で停止します。`pip --user` の実行ファイルが見つからない場合は、`py -3 -m site --user-base` で場所を確認し、その下の `Python3xx\Scripts`（例：`%APPDATA%\Python\Python313\Scripts`）をユーザーPATHへ追加して、ターミナルを開き直してください。追加パッケージをアプリが自動インストールすることはありません。設定ファイル・保管庫・状態ファイルはGitHubへ追加しないでください。

## 毎回の操作

1. 「一覧を更新」で受け箱を読みます。`.gdoc`は無視し、壊れたJSONはそのファイルだけ「要確認」にします。
2. 不要な動画を選んで「弾く」。理由は候補から選ぶか自由に入力できます。空欄でも弾けます。印は再起動しても残ります。「弾いた動画も表示」→ 選択 →「戻す」で解除できます。
3. 必要なら手動URLを1行に1本貼ります。短縮URL・時刻付きURLも受け付けます。
4. URL欄だけを処理する場合は「手動保存」、一覧のチェックを付けた行だけを処理する場合は「選択保存」を押します。未選択・弾いた行には保存しません。選択なしは何もしません。**押すことが、その対象へのGitHub・Notebook保存の許可です。** 追加の確認画面はありません。
5. 工程・待ち理由・Notebook使用数を確認します。1本の失敗でも別の動画の処理は進みます。処理中は画面を閉じず、終了を待ってください。

一覧の先頭のチェックをクリックして選び、「全部選ぶ／全部外す」も使えます。弾いた動画にはチェックできません。一覧更新時に情報のみを取得し、チャンネル・公開日・言語の取得済み値は保管庫にキャッシュします。テーマは受け箱に無ければ「未設定」です。情報が取れない場合は理由を表示し、同じ画面では繰り返し取得しません。原因を直してから再起動してください。

受け箱にあるチャンネル・公開日・言語は優先し、不足する行だけ情報を取得します。取得中は一覧に「取得中…」と表示します。窓は毎回1280×840で開き、位置やサイズの保存はブラウザに従います。一覧の右側の列は下のスクロールバーで表示できます。

## 保存した動画内容をAIに質問

「保存した動画内容をAIに質問」で質問欄を開き、2000文字以内で入力して「Claudeへ質問を送信」を押します。保存済み `research/` の関連ノートを最大3件、合計24000文字まで送ります。字幕全文は送りません。送信内容と回答は保管庫の `subtitle-switch-state/question_logs/questions.jsonl` に保存されるため、内容を確認してから送ってください。根拠資料と、そのノートにある時刻リンクを回答に添えます。

Grokは無効です。公式CLIは案内されていますが、WindowsでAPIキーを使わず購読で実行できる条件は **UNKNOWN** です。Claudeも実機では未確認です。

## 待ちになったら

- `NOTEBOOK_LOGIN_EXPIRED`：「保存」を押すと、作業を始める前にログインを確認し、切れていればnotebooklm-pyのログイン画面だけを開きます。オーナーがGoogleにログインしてから、もう一度「保存」を押します。アプリはパスワードを入力・保存しません。字幕・研究ノートの作り直しは不要です。
- `YOUTUBE_ROBOT_CHECK`：YouTube側の確認をオーナーが解決します。自動再ログインやロボット確認の回避は行いません。
- `CLAUDE_QUOTA`：Claudeの枠が戻るまで研究ノート待ちです。別モデルへ切り替えません。
- `NOTEBOOK_CAPACITY`：Notebook工程だけ待ちです。GitHub保存までは済んでいます。保存先Notebookや上限設定を確認してください。
- `WRITE_RESULT_UNKNOWN`：結果不明の書き込みです。再起動後も再送せず読み戻します。確認できなければ待ちを維持します。状態ファイルを削除してやり直さないでください。
- `SAVE_BRANCH_REQUIRED`：GitHub作業フォルダが設定した専用ブランチか確認してください。

原因を直した場合だけ、画面の「直した原因」を選んで対象を選んで対応する保存ボタンを押します。原因を変えた再試行は2回まで。同じ原因を直さずに押しても再実行しません。結果不明の書込みはこの操作でも再送しません。pushの非0終了が記録されている場合だけ、まず読み戻し、未保存なら記録済みの同じコミットを非force・fast-forwardで再pushします。新しいcommitは作らず、競合時は止まります。

Notebookログイン切れとYouTubeロボット確認の待ちは、アプリを再起動しても残ります。新しく受け箱に届いた動画も該当工程で待ちます。原因を直してから「直した原因」を選ぶと再開できます。Notebook待ちの間も、新しい動画の字幕・研究ノート・GitHub保存までは進みます。

## 好みメモとPC上の資料

好みメモは `preferences_YYYYMMDD.json`、同日2回目は `_2`、以後連番です。seedは変更しません。字幕本文・キーは含めません。Driveへ書けない場合は保管庫内の `subtitle-switch-state/preference_outbox/` に残り、次回まとめて送ります。送信待ち件数を画面に表示します。

字幕と研究ノートの作業資料は保管庫内 `jobs/<動画ID>/`、進行状態は `subtitle-switch-state/inventory.json` に保存します。GitHubへは検品した短い研究ノートと台帳・索引だけを送ります。Notebookには字幕原文OKFと研究ノートOKFの独立2ソースを登録し、URL単体ソースは登録しません。

`research_from_url.ps1` と旧画面の互換用関数は試作の参照として残しています。新しい画面はそのPowerShell経路を起動しません。

「完了・登録済みも表示」で処理結果を見返せます。通常の一覧には未処理・待ち・要確認だけを出します。

`CLAUDE_API_CONFIGURATION_BLOCKED` は、ClaudeをAPIキーや他providerへ接続する環境変数が設定されている場合です。アプリは値を読み取らずモデル起動前に停止します。通常のClaude CLIログインを使う環境をオーナーが確認してください。

保存済み字幕の指紋不一致や、字幕に存在しない開始秒へのリンクは検品で停止します。保管庫の字幕を手で書き換えないでください。GitHubへ送るノートの実ファイルも、検品済みノートとの一致を再確認します。

## Claude CLI引数の確認（2026-10-27）

[公式CLI reference](https://code.claude.com/docs/en/cli-reference) に `--effort` の `medium` と、`--tools` のカンマ区切りツール名指定が記載されています。このアプリは `--effort medium` / `--tools Read,Write` を渡します。オーナーPCのCLIバージョンでの受付はUNKNOWNです。モデル起動なしの `claude --help` で確認できます。

`--setting-sources` 自体は公式資料にありますが、空文字 `''` が全設定を除外するか、Windowsの `.cmd` 経由で空引数が保たれるかはUNKNOWNです。安全設定を黙って外す代替起動はしません。引数エラーは `RESEARCH_FAILED` として止めます。常に付く `usage` メタデータだけでは枠切れと判定しません。

画面は白地と赤のアクセント、要確認行は淡いピンクです。アイコンはコードで描き、外部画像や追加パッケージを使いません。日本語はWindows標準のYu Gothic UIを指定しています。配置・色・絵柄のオフライン試験は行いますが、Windowsのタイトルバー・タスクバー・実際の表示と操作感はUNKNOWN（オーナー確認）です。
