## 変更内容（PR本文用）

見出し左の赤い本を、決定版 `icon_v3_2_512.png` に差し替えた。
見出しの文字・蜜柑の「猫」・保存ボタンの本のマークはそのまま。
既存の Issue #36 の favicon は同じPNGを参照しており、変更しない。
見出し画像も既存の認証つき同一オリジン配信を使い、CSPは
`img-src 'self' data:` のまま。静止プレビューにも同じ変更を反映する。

起動中の再起動は、Windowsのローカル名前付きパイプで既存プロセスへ表示依頼を渡し、
応答を確認して静かに終了する。起動途中は最初の窓が現れるまで待ち、追加の窓を作らない。
既存のChrome/Edgeアプリ窓は最小化されていれば復元して前面表示を要求する。
窓を閉じた後もサーバーが終了するまでの猶予中なら、同じURLで再表示する。
最初の窓を検出する前に閉じた場合も、既存の終了通知とブラウザ窓の有無で判断する。
読み込み中や再読み込み中のブラウザ窓が残っていれば、追加の窓を作らず待つ。
既存プロセスが終了中で依頼を適用しなかった場合は、ロックの解放後に通常起動する。
窓を閉じた際の終了条件、処理中の終了待ち、既存のデスクトップ起動は維持する。
最大化中の窓の大きさは変えない。

認証付きURLは既存プロセスのメモリ内だけに保持し、IPCにもファイルにも書き出さない。
IPCは固定の表示依頼とPID・結果だけをバイト列で扱い、pickle入力を受けない。
結果が不明の依頼は再送しない。ポート使用中等の本当の起動失敗は従来の
エラーダイアログとログへ送る。新しいパッケージは追加しない。

新たに開いたアプリ窓をタイトルとウィンドウクラスで見つけ、
`app-icon-v3-2.ico` を小アイコン（タイトルバー）・大アイコン（タスクバー用）として
`WM_SETICON` で設定する。起動前からあった同名窓は対象にしない。
既存の決定版PNG faviconも維持する。Windowsでの最終的な表示と前面表示の可否は
実画面で未検証（UNKNOWN）。ブラウザやOSの挙動は以下の手順で確認する。

## タスクバーのボタン統合を今回採用しない理由と代替案

現在のピン留め対象は PowerShell の `.lnk`、表示する窓の所有者はChrome/Edgeであり、
異なるアプリとして扱われる。Windowsの統合にはショートカットと窓の
AppUserModelIDをそろえる必要がある。PythonのプロセスID設定だけでは、
別プロセスであるブラウザ窓のIDは変わらない。
Chromiumの `--app` 窓はブラウザ・アプリ・プロファイルからIDを作る。
現行のローカルサーバーは起動ごとにポートと認証URLが変わり、
既存のピン留めショートカットを管理するコードもこのリポジトリにはない。

今回、既存のデスクトップ起動を保ったまま、そのショートカットと
ブラウザ管理のIDを確実に一致させる変更は採用しない。
ボタン1個への統合は未達。Issueで許容された代替としてアイコンの統一までとする。
窓の大小アイコン設定とfaviconが実画面に反映されることはWindowsでの確認が必要。
ショートカット自体のアイコンは、Windows側のプロパティで決定版
`automation/subtitle-switch/assets/app_icon/app-icon-v3-2.ico` を選べる。

今後の候補:

- Windows側でショートカットの生成・更新を管理し、実際のブラウザ窓のIDと合わせる。
  既存プロファイル、Chrome/Edge両対応、再起動後のID、ピン留めからの再起動を実機検証する。
- ブラウザのインストール済みアプリ用ショートカットを使う。
  固定したアプリ識別・URLと、サーバーを起動する入口を先に設計する必要がある。
  現在の一時URLを直接ピン留めする方式は再起動後に使えない。
- 将来、単独のWindows窓を持つホストへ移す。例えばpywebview等を使う案は
  新しいパッケージが必要なので提案のみ。今回の依存追加はない。

## Windows確認手順（実画面はUNKNOWN）

1. 既存のデスクトップ「字幕アプリ起動」と、タスクバーの登録済みボタンから各々起動する。
   黒い端末や汎用エラーダイアログが出ないことを確認する。
2. 起動直後の数秒以内に起動ボタンを繰り返し押す。開く窓は1つであることを確認する。
3. 最小化し、別アプリを前面にしてからもう一度起動する。
   同じ窓が復元され前面に出ることを確認する。開いている保存処理は開始しない。
4. 窓を閉じた直後にもう一度起動する。画面が1つだけ再表示されることを確認する。
   さらに窓を閉じて従来の終了猶予を過ぎてから起動し、新たに開けることを確認する。
5. タイトルバー左上、見出し左、起動中のタスクバーが決定版の司書猫か確認する。
   見出しの文字と蜜柑の「猫」、保存ボタンの本は変わっていないことを確認する。
6. ChromeとEdgeのそれぞれが選ばれる環境で確認する。
   ブラウザやWindowsが古いアイコンをキャッシュしている場合は窓を閉じて再起動する。
7. ピン留めのボタンと起動中のボタンは今回分かれる可能性がある。
   1ボタン化の成功とは報告せず、上記の制約と代替案を引き継ぐ。
