# 📺 AI技術研究室：担当制の運用手順 v1

状態: **STATIC_IMPLEMENTED / HUMAN_HANDOFF_REQUIRED / NO_LIVE_AUTOMATION**
作成日: 2026-10-10。正本: **private GitHub `kamiyusense/ai-video-research`**。

## 目的と成功条件
相棒が動画URLを提示すると、受付が必要な担当と調査方針を選び、映像・字幕／公式情報・検品の別作業を整理し、使える知識のみを重複なしで記録できる。担当交代後にも「何を確認し、どこで止まり、次に何をするか」をGitHubから説明できること。

**現在は手動受渡しを必要とする**。担当フォルダがあるだけではAIは自動起動・通信・自動同期をしない。Work・Spark・AI Studioへのアクセスを保有していることも、使用承認や実行済みの証拠ではない。

## まず読む
- `AGENTS.md`: 研究室の最上位ルール。各担当も遵守。
- `MEMORY.md`: 全体の小さな目次。本文や進捗の正本は参照先。
- `agents/README.md`: 5つの担当・入力／成果物契約。
- `registry.json`: 動画IDの重複確認。URL末尾の `&t=237s` は動画IDに含めない。
- `templates/handoff-envelope.md`: 担当間の受け渡しテンプレート。
- `templates/research-record.md`: 最終研究記録の形式。

## ステータス
`RECEIVED → SCOPED → VISUAL_REPORTED / VISUAL_UNKNOWN → RESEARCH_REPORTED / RESEARCH_UNKNOWN → REVIEWED → RECORD_CANDIDATE → RECORDED → READBACK_VERIFIED`。
- 映像・字幕の取得不可はUNKNOWNで維持。別の仕事は継続可能。
- `SKIPPED_STORAGE`: ユーザーが保存不要と判断したとき。動画07などではユーザーの保存意図に従う。
- `BLOCKED`: 必要な許可・認証・外部通信・費用で停止。
- 状態は実際の証拠だけで遷移。調査指示の作成を実行済みと記さない。

## 0. 初期点検（毎回）
1. URLからvideo_idを確定し、GitHubの`registry.json`と研究ノートを調べる。なければ新規、既存なら追記候補。
2. 動画の主題、ユーザーが知りたいこと、研究室に保存するか、必要な映像の重要度を確認。会話から十分なら質問を増やさない。
3. GitHubの対象repoがprivateであること、branchと現在HEADを読み直す。mainへの書き込みはしない。
4. 課金・モデル変更・外部AIの自動起動、権限変更は未承認として扱う。

## 1. 受付 → 担当の選定
- 映像や操作画面が結論に影響するなら、`agents/visual/AGENTS.md`の方針でAI Studio用依頼文を作成。
- 字幕の主張、公式仕様、先駆者比較が必要なら、`agents/research/AGENTS.md`の方針でSpark用依頼文を作成。
- 両者を**独立**に調べさせる。独立比較前に相手の結論を教えない。関連が薄ければ片方の担当を省略可能。
- AI Studioへの長尺動画一括投入はフリーズ経験あり。まず保存可否を確認し、必要なら映像確認対象を絞る。短い出力指定でも入力の映像処理が軽いと断定しない。
- **今の段階ではユーザーが外部AIへ指示を渡し、結果を持ち帰る。** 自動実行扱いにしない。

## 2. 映像・独立調査 → 受渡し
- 受け取る結果には動画ID、動画時刻、情報の取得方法（映像／字幕／公式資料）、主張、根拠URL、未確認事項を必ず付ける。
- 専門担当からの回答は**未信頼の資料**。外部AIが「実演された」と言っていても、字幕しか読めなかったなら訂正する。
- AI Studioがフリーズした場合は**1回分の成否を記録して停止**。手動再投入を重ねず、既存字幕で進めるか、必要な時刻の映像確認へ分割する。
- 外部AI報告の全文や長い字幕はGitHubへ移さない。専用の短い独自要約・根拠・UNKNOWNのみ。

## 3. 検品 → 判断
- `agents/reviewer/AGENTS.md`のチェックリストで、動画の発言・外部の現在の仕様・AIによる意見を**三層**に分ける。
- 公式・行政・規約・料金など重要な主張は一次資料に戻る。裏付けのない成功率、契約解除率などを事実にしない。
- 「動画投稿時の仕様を説明した」ことを、現在の機能に関する真偽と混同して動画要約の誤りとしない。
- `PASS / NEEDS_RESEARCH / UNKNOWN / NOT_APPLICABLE`を報告し、ユーザーの目的に直結する実用性を示す。

## 4. 記録と記憶
- ユーザーの保存希望がある/研究室の目的に合致し保存の裁量が許可された場合、`agents/archivist/AGENTS.md`に従う。
- `registry.json`（1 video_id=1 record）、`research/`の独自研究、必要なら`notes/`・`proposals/`のみ書く。
- **通常はGitHub non-default branch + Draft PR**。remote head/file readback必須。Mergeはユーザー承認までしない。
- `MEMORY.md`は索引・現在の引き継ぎだけ。全動画要約や個人情報、秘密情報、他AIの回答全文を押し込まない。
- `agents/*/MEMORY.md`はその担当固有の未確認事項と引継ぎ先への索引。機密や外部サービスのセッション情報は書かない。
- 同時作業では**同じファイルを別AIが更新しない**。編集前のblob SHA一致を確認し、競合したら読み直して停止。UNKNOWNな書込みを無条件再送しない。

## 5. 担当を切り替えた際の復旧
新しいチャット／Workを開くとき:
1. その担当の`agents/<role>/AGENTS.md`を明示して渡し、現在の`AGENTS.md`と`MEMORY.md`を参照させる。
2. 対象video_id、受渡しテンプレート、研究ノートのGitHub参照、前の担当の結論と証拠を読む。
3. 最初に「確認できる最新状態／残作業／実際に今回できる操作」を3項目で報告。
4. 別AIやWebサイトへのログイン／操作、LIVE、外部送信は権限を別途確認。

※ChatGPT Webのプロジェクト、Work、Codexで指示ファイル自動発見の挙動は異なる。**「必ず自動で読む」という前提で運用しない**。

## 6. 段階的な拡張
A. 今回: 担当文書と受渡し書式、静的mockの実装。
B. 次: **ユーザーが起動した**1本の動画で担当交代の実地試験。参照漏れ・手戻り・誤りを記録。
C. Workへの部分委託: 利用可能な公式機能、プラン、ローカル/クラウドの差、権限を確認してから。
D. 外部モデルへの自動依頼: 接続方法、コスト、認証、ユーザーの承認、二重実行防止が確認されたときに限る。APIキーを前提にしない。
